# Orca 튜토리얼: 기능별 현업 활용 설명 (필수 교육 콘텐츠)

> 이 문서는 제품 요구사항과 교육 콘텐츠 초안입니다. **현재 UI에 모든 설명이 구현된 것은 아닙니다.** 아래 사례는 교육용 실무 시나리오이며 특정 회사의 검증된 업무 관행이라고 주장하지 않습니다.

| 기능 | 왜 쓰나 | 현업 예시 | 완료 시 결과/주의점 |
|---|---|---|---|
| Quick Open (`Ctrl+J` / `⌘ J`, 버전 검증 필요) | 여러 작업 맥락을 빠르게 전환 | 로그인 버그를 고치다가 결제 기능 Worktree로 이동 | 올바른 프로젝트/브랜치에 있는지 확인 |
| 새 터미널 탭 | 작업별 명령 실행을 분리 | 개발 서버를 유지하며 다른 탭에서 Git 상태 확인 | 실행 중인 서버를 실수로 종료하지 않기 |
| 파일 검색 | 대규모 코드에서 특정 파일 탐색 | 로그인 버튼 컴포넌트를 빠르게 찾아 수정 | 파일명이 비슷할 때 경로 확인 |
| GitHub Clone | 팀 저장소를 로컬로 가져와 작업 시작 | 신규 팀원이 앱 저장소를 받아 빌드 | 접근 권한 및 비밀정보 취급 주의 |
| Workspace | 작업 단위와 에이전트 실행 맥락 정리 | 버그 수정과 신규 기능을 서로 다른 작업 공간에서 진행 | Workspace와 Git Worktree를 동일 개념으로 단정하지 않기 |
| Git Worktree | 같은 저장소에서 브랜치별 독립 폴더 사용 | UI, API, 테스트를 서로 다른 에이전트가 병렬 작업 | 공유 설정/DB/포트 충돌은 별도로 관리 |
| 터미널 4분할 | 여러 프로세스/에이전트 상태를 한눈에 보기 | UI 에이전트, API 에이전트, 테스트, 서버 로그 동시 모니터링 | 4분할이 작업 격리 자체를 제공하지는 않음 |
| 여러 프로젝트 열기 | 제품 간 빠른 전환 | Flutter 앱과 별도 백엔드 저장소를 번갈아 작업 | 서로 다른 프로젝트의 2×2 고정 배치는 버전별 확인 |
| AI 병렬 에이전트 | 독립 작업을 동시에 진행해 대기 시간 줄이기 | 로그인 UI, Firebase 인증, 테스트를 별도 Worktree에서 작성 | 파일 소유권/인터페이스를 먼저 정의하고 리뷰·테스트 후 병합 |
| PR 및 코드 리뷰 | 변경 내용을 팀이 확인하고 품질 보증 | 에이전트가 작성한 변경을 PR로 제출하고 CI 확인 | 자동 생성 코드를 무검토 병합하지 않기 |

## 튜토리얼 화면의 각 단계에 반드시 포함할 필드 (추가 구현 필요)
- **지금 할 일**: 실제 버튼/키/입력 값
- **왜 하는가**: 이 기능이 해결하는 문제
- **현업에서는**: 실제 프로젝트에서의 구체적인 사용 장면
- **성공하면**: 확인 가능한 화면/출력
- **주의할 점**: 권한, 데이터 손실, 충돌, 버전 차이

## 현업 종합 실습
Flutter 로그인 기능 개발을 예시로, UI/인증/테스트 작업을 분리하고 각 Worktree에서 에이전트를 실행한 다음 `flutter test`와 PR 리뷰를 진행합니다. 인증 설정과 비밀 키는 프롬프트에 노출하지 않고, 통합 전 각 변경의 Diff를 확인합니다.
